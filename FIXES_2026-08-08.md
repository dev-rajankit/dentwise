## 1. Double booking (the important one)

### Symptom
Two different patients booked **Dr. Aamish Husain, 2026-08-09 at 09:00**. The two
rows were created **1.9 seconds apart** — the race condition caught on camera.

### Name of the problem
**Double booking**, caused by a **check-then-act race condition**, also known as
**TOCTOU** (time-of-check to time-of-use): availability is checked at one moment
and written at a later moment, with nothing guaranteeing the world didn't change
in between.

### Three stacked holes

| # | Where | Problem |
|---|---|---|
| 1 | `src/lib/actions/appointments.ts` | `bookAppointment` did **zero** conflict checking. The only guard was a disabled button — useless across two browsers. |
| 2 | `src/hooks/use-appointment.ts` | `queryKey: ["getBookedTimeSlots"]` omitted `doctorId`/`date`. React Query served one doctor/date's slots from cache for a *different* doctor/date, so booked slots showed as free. |
| 3 | `prisma/schema.prisma` | No uniqueness constraint. Even with a server check, two concurrent requests both read "free" and both insert. |

Fixing #1 and #2 closes the common case. **Only #3 makes it impossible** — the
database is the single point where concurrent writes serialize.

### Fix A — the database constraint (the real guard)

```prisma
model Appointment {
  // ...
  @@unique([doctorId, date, time])
  @@index([doctorId, date])   // makes getBookedTimeSlots a lookup, not a scan
}
```

Postgres serializes concurrent inserts against a unique index, so the second one
*always* loses. Everything else is a nicety layered on top.

### Fix B — server action

`src/lib/actions/appointments.ts`:

- Pre-checks for a conflict (fast, friendly message)
- Catches Prisma **`P2002`** (unique violation) for when the pre-check loses the race
- Added `toDateOnly()` so `"2026-08-09"` always normalizes to the same UTC midnight
  — the constraint compares exact timestamps, so an inconsistent time component
  would silently defeat it
- Moved auth/validation **outside** the `try`. Previously every error was swallowed
  and rewritten as `"Failed to book appointment. Please try again later."`, so a
  conflict message could never have surfaced.

### Fix C — two Next.js constraints discovered the hard way

**C1. A `"use server"` file may only export async functions.**

Not classes, not `const`, not objects. `tsc --noEmit` does **not** catch this — it's
an RSC constraint, not a type error. It only appears at build/compile time:

```
Only async functions are allowed to be exported in a "use server" file.
```

First attempt used `export class SlotUnavailableError` → failed.
Second attempt used `export const SLOT_TAKEN_MESSAGE` → also failed.
Final: module-local `const`, no export. (`export type` is fine — types are erased.)

**C2. Next.js redacts thrown server-action errors in production.**

`throw new Error("That slot is taken")` works on localhost but shows a generic
digest on Vercel. So failures are returned **as data**, and the hook converts them
back into a rejection client-side:

```ts
// appointments.ts — failure travels as a return value, not a throw
export type BookAppointmentResult =
  | { success: true; appointment: ReturnType<typeof transformAppointment> }
  | { success: false; message: string; slotTaken?: boolean };
```

```ts
// use-appointment.ts — re-throw so React Query's onError works unchanged
mutationFn: async (input) => {
  const result = await bookAppointment(input);
  if (!result.success) throw new Error(result.message);
  return result.appointment;
},
```

### Fix D — the cache-key bug

```diff
- queryKey: ["getBookedTimeSlots"],
+ queryKey: ["getBookedTimeSlots", doctorId, date],
+ staleTime: 0,
+ refetchOnWindowFocus: true,
```

**This bug alone could produce a double booking with no concurrency at all.**

### Fix E — UX

On conflict the user is returned to step 2 with `selectedTime` cleared and
availability refetched, instead of being stranded on a dead confirmation screen.

### Verified

Not just that the index exists — that it *bites*. A deliberate duplicate insert was
attempted:

```
appointments_doctorId_date_time_key
  CREATE UNIQUE INDEX ... ON appointments ("doctorId", date, "time")

Attempting duplicate insert...
  OK: rejected with P2002 on [doctorId,date,time] — constraint is live.
```

### ⚠️ Future gotcha: adding `CANCELLED`

`AppointmentStatus` currently has only `CONFIRMED` and `COMPLETED`. That is the only
reason a plain `@@unique` works. **The moment you add cancellation this constraint
becomes wrong** — a cancelled 09:00 slot would block that slot forever.

You'd need a **partial unique index**, which Prisma cannot express in schema syntax.
Write it as raw SQL in a migration:

```sql
CREATE UNIQUE INDEX unique_active_slot ON appointments ("doctorId", date, time)
  WHERE status <> 'CANCELLED';
```

### ⚠️ `duration` is currently ignored

`duration` is stored (default 30 min) but the constraint only matches exact `time`
strings. **A 60-minute appointment at 09:00 does not block 09:30.** Proper fix is a
different shape: store `startsAt`/`endsAt` as timestamps and use a Postgres
`EXCLUDE` constraint with `tstzrange` overlap.

## 2. Turbopack panic loop / endless recompiling

### Symptom
`npm run dev` spammed `FATAL: An unexpected Turbopack error occurred` and the page
appeared to recompile forever.

### Root cause
The `compile:` numbers were mostly 13–80ms — it **wasn't** actually recompiling.
It was **panic → reload → panic**.

`.next/` contained **two incompatible layouts side by side**. Commit `bcf608f`
upgraded to Next 16, but nobody cleared the cache. Next 16 relocated dev artifacts
to `.next/dev/`, leaving:

- `.next/build-manifest.json`, `.next/static/`, `.next/server/`, `.next/cache/webpack/` ← Next **15**
- `.next/dev/` ← Next **16**

Turbopack read a stale Next 15 manifest whose module graph pointed at a
`node_modules/next` layout that no longer existed. The panic log said:

```
Failed to write app endpoint /appointments/page
Caused by: - Next.js package not found
```

…even though `next@16.1.1` was installed perfectly fine (`require('next/package.json')`
resolved it). Each panic killed the HMR socket → dev overlay hard-reloaded → fresh
`GET /` + server action `POST /` → panic again.

`Failed to benchmark file I/O (os error 3)` at startup was the same stale cache.

### Fix

```bash
rm -rf .next
```

Startup went **24.9s → 3.5s**, zero panics.

> **Rule: any time you change Next.js major versions, `rm -rf .next` is part of the
> upgrade.** The panic message names a *missing package*, which sends you hunting
> through `node_modules` — the wrong place entirely.

### Bonus gotcha: `EPERM` on `prisma generate`

```
EPERM: operation not permitted, rename '...query_engine-windows.dll.node.tmp' -> '...'
```

Orphaned `node` processes were holding the DLL. Stopping a dev server via a process
manager often kills the `npm` wrapper but **not** its children (`next dev`,
`start-server.js`, `postcss.js`). Check command lines before killing — plain `node`
processes may belong to your editor:

```powershell
Get-CimInstance Win32_Process -Filter "Name='node.exe'" |
  Select-Object ProcessId, CommandLine
```

## 3. Cropped & squashed images

### Symptom
Right-side landing images appeared cut off and distorted.

### Root cause — two compounding problems

**Every PNG in `public/` is 1024×1536 (2:3 portrait)** except `logo.png` (1024×1024).
The code declared them as **squares**:

| File | Declared | Actual |
|---|---|---|
| `Hero.tsx` | `600 × 600` | 1024 × 1536 |
| `CTA.tsx` | `300 × 300` | 1024 × 1536 |
| `WhatToAsk.tsx` | `500 × 500` | 1024 × 1536 |
| `HowItWorks.tsx` ×3 | `40 × 40` | 1024 × 1536 |

Next.js renders `<img width height>` from those props, and **the browser derives
`aspect-ratio` from the attributes, not from the file**. A square box for a tall
image squashes it.

**Second problem** — `Hero.tsx` was:

```
h-screen ... overflow-hidden
```

`h-screen` pins height to exactly 100vh and `overflow-hidden` clips anything taller.
That was the genuine *cropping*.

### Fix

```diff
- <section className="relative h-screen flex items-center overflow-hidden pt-20">
+ <section className="relative min-h-screen flex items-center overflow-hidden py-20">
```

```diff
- width={600} height={600} className="w-full h-auto"
+ width={1024} height={1536} priority
+ sizes="(max-width: 1024px) 90vw, 45vw"
+ className="mx-auto w-auto h-auto max-h-[clamp(26rem,80vh,46rem)] max-w-full object-contain"
```

### Why `min-h-screen` permanently fixes cropping

`min-height` with `height: auto` means the box **grows** to contain its in-flow
content, so the image can never overflow its own section. `overflow-hidden` now only
clips the decorative gradient orbs — which is what it was there for. Making the image
larger just pushes more below the fold and the page scrolls.

Also added `sizes` (so Next serves a scaled file, not the full 1024px original) and
moved `priority` from the CTA image (below the fold) to the hero image (the real LCP
element).

## 4. Dead navbar links

### Symptom
"How it Works", "Pricing", "About" did nothing.

### Root cause
All three were literal `href="#"` placeholders, and **no section had an `id`** to
jump to.

### Fix

| Section | Heading | `id` |
|---|---|---|
| `HowItWorks.tsx` | "Three steps to…" | `how-it-works` |
| `PricingSection.tsx` | "Choose your…" | `pricing` |
| `WhatToAsk.tsx` | "Ask about…" | `about` |

Plus `scroll-smooth` on `<html>` in `layout.tsx`, and the footer's "How it works" /
"Pricing" (same `href="#"` bug) repointed.

### ⚠️ `scroll-mt-20` is required, not cosmetic

The header is `fixed` and `h-16` (64px). Without a scroll margin, an anchor jump puts
the section's top edge at viewport y=0 — **underneath the header** — hiding the
heading and looking like it scrolled to the wrong place. `scroll-mt-20` (80px) parks
it just below.

### Note
**"About" is a guess.** There is no About section. It points at `WhatToAsk`, the only
unclaimed content section. Revisit if a real About page is built.

## 5. Sections too tall on short screens

### Symptom
Clicking a nav link landed correctly but showed only the heading and *half a card*.

### Root cause
Spacing was **fixed-size** (`py-32` = 128px, `mb-20` = 80px), tuned for a tall
monitor. A 1366×768 laptop is **wide but short** — it clears every `lg:` breakpoint
and gets full desktop spacing inside ~620px of usable viewport:

```
128px  section top padding
 ~40   badge
 ~24   gap
~150   two-line heading at text-6xl
 ~24   gap
 ~60   subtitle
  80   mb-20
─────
~506px consumed before the first card    → ~90px left for content
```

### Fix — scale with viewport **height**, not width

| | Was | Now |
|---|---|---|
| Section padding | `py-32` (128px) | `py-[clamp(3rem,7vh,8rem)]` |
| Heading gap | `mb-20` (80px) | `mb-[clamp(2rem,5vh,5rem)]` |

Applied to `HowItWorks`, `WhatToAsk`, `PricingSection`, `CTA`.

On a 620px viewport → **48px / 32px** (reclaims ~128px). On 1080p → 76px/54px. On a
tall display → back to the original airy spacing. The `clamp` floor stops it
collapsing on phones.

### ⚠️ Gotcha: Tailwind v4 `@utility` silently did nothing

These were first written as `@utility section-py { … }` in `globals.css`. They
compiled to **nothing** — the CSS chunk never rebuilt, and there was no error. Since
arbitrary values (`py-[clamp(...)]`) were already proven to work in this project,
that's what shipped. More verbose in JSX, but it demonstrably compiles.

> **Always grep the compiled CSS for a new utility before trusting it.**

## 6. Invisible doctor profile images

### Symptom
Broken-image glyph + alt text everywhere a doctor avatar appeared.

### Root cause — two separate problems

**1. The avatar host is dead.** Every `imageUrl` pointed at `avatar.iran.liara.run`.
DNS resolves; the connection fails:

| Host | Result |
|---|---|
| `avatar.iran.liara.run` | **000 — unreachable** |
| `randomuser.me` | **000 — unreachable** |
| `api.dicebear.com` | 200 ✓ |
| `images.unsplash.com` | responds ✓ |

Network was fine — the host is simply down/blocked. `unoptimized: true` in
`next.config.ts` means the browser fetches these URLs directly.

**2. The existing fallback guarded the wrong condition.** ← *the real lesson*

```tsx
{dentist.imageUrl ? <Image … /> : <initials />}
```

That tests whether the URL is **missing**. It was *present* — it just failed to
**load**. A ternary on a string cannot detect a failed network request, so the
fallback was unreachable in exactly the situation it existed for.

### Fix

**New `src/components/DoctorAvatar.tsx`**, built on the existing Radix `Avatar`.
`AvatarImage` unmounts itself on load **error**, so `AvatarFallback` covers a dead
host, a 404, *and* a missing URL. Initials strip the honorific, so
"Dr. Aamish Husain" → **AH**, not DA.

Replaced 4 call sites that previously had 3 different ad-hoc fallbacks:
`appointments/page.tsx`, `DoctorInfo.tsx`, `DoctorSelectionStep.tsx`,
`DoctorsManagement.tsx`.

**`src/lib/utils.ts` — `generateAvatar()`** was the *source* of the dead URLs, so
every newly added doctor would have inherited the bug:

```ts
export function generateAvatar(name: string, gender: "MALE" | "FEMALE") {
  const username = name.replace(/\s+/g, "").toLowerCase();
  const seed = encodeURIComponent(`${username}-${gender.toLowerCase()}`);
  return `https://api.dicebear.com/9.x/avataaars/svg?seed=${seed}`;
}
```

### Notes

- **`remotePatterns` for `avatar.iran.liara.run` in `next.config.ts` is now dead
  config.** Left in place (harmless).
- **`api.dicebear.com` was deliberately NOT added to `remotePatterns`** — Radix
  renders a plain `<img>`, bypassing Next's image optimizer. **If you ever switch
  these back to `next/image`, you must add it** or images break again.
- **Gender is now cosmetic.** The old service had explicit `/boy` and `/girl`
  endpoints. DiceBear's `avataaars` has no gender parameter, so gender is folded
  into the seed — variants differ, but won't reliably *look* gendered.

## 7. Database changes (applied to production)

Target: **Neon Postgres** (`neondb`, `ep-morning-moon-a4y6cb4w-pooler.us-east-1.aws.neon.tech`).
The project has **no `prisma/migrations/` folder** — it uses `prisma db push`.

### 7.1 Schema

```sql
CREATE INDEX "appointments_doctorId_date_idx" ON appointments ("doctorId", date);
CREATE UNIQUE INDEX "appointments_doctorId_date_time_key" ON appointments ("doctorId", date, "time");
```

`db push` demanded `--accept-data-loss`. **That warning is boilerplate** about the
constraint possibly *failing*, not about deleting data. It was verified first with:

```bash
npx prisma migrate diff --from-schema-datasource prisma/schema.prisma \
                        --to-schema-datamodel  prisma/schema.prisma --script
```

…which showed the entire change was two `CREATE INDEX` statements — no `DROP`, no
`ALTER COLUMN`. **Always run that diff before passing `--accept-data-loss`.**

### 7.2 Data: one appointment deleted

The unique index cannot be created while duplicates exist, so this had to happen first:

```
Dr. Aamish Husain — 2026-08-09 @ 09:00
  KEPT     cmsk2wmxn0001gwxcytsqsuhd  ankitrajkumar1546024@gmail.com  07:55:20.987Z
  DELETED  cmsk2wodi0003gwxcf2ya31w1  pooja9315829906@gmail.com       07:55:22.854Z  (+1.9s)
```

Policy applied: **first booking wins**, matching how the code now behaves.

> ⚠️ `pooja9315829906@gmail.com` no longer has that appointment and **was not notified**.

### 7.3 Data: 4 doctor avatars backfilled

All 4 rows repointed from the dead host to DiceBear. Verified each returns
`200 image/svg+xml`.

### Reproducing on another environment

1. `npx prisma generate`
2. Find duplicates before pushing:
   ```sql
   SELECT "doctorId", date, "time", COUNT(*)
   FROM appointments GROUP BY 1,2,3 HAVING COUNT(*) > 1;
   ```
3. Delete the losers, then `npx prisma db push --accept-data-loss`
4. Backfill any `imageUrl LIKE '%liara.run%'` using `generateAvatar()`

## 9. Zustand review (analysis only — nothing implemented)

**Verdict: the store works and nothing above required changing it.** Reviewed on
request; left as-is.

It also now interacts *safely* with the double-booking fix: the store keeps
`selectedDate`/`selectedTime` for the session, so a user who abandons at step 3 and
returns resumes with a stale slot. That used to be a way to double-book. Now the DB
constraint rejects it and `onError` bounces them to step 2 with fresh availability —
staleness degrades safely.

Findings, ranked:

1. **No selectors — whole-store subscription.** `const { …12 fields } = useAppointmentStore()`
   with no selector subscribes to the entire store, so every `set()` re-renders the
   whole page including the doctor list. Invisible at this scale, but the classic
   Zustand anti-pattern. Fix: `useShallow` or per-field selectors. *(The one worth doing.)*
2. **`bookedAppointment` is never cleared.** `resetBookingForm()` resets five fields
   but not this one; it lingers all session.
3. **Three dead actions** — `setSelectedDentistId`, `goToNextStep`, `goToPreviousStep`
   have **zero** uses. The page calls `setCurrentStep(n)` directly in 7 places.
4. **The `Appointment` type provides no safety.** The store declares `reason: string`
   but Prisma's is `String?`. More importantly `transformAppointment()` returns `any`
   — verified with `type IsAny<T> = 0 extends 1 & T ? …`, which resolved to `IS_ANY`.
   So `setBookedAppointment()` accepts anything, and `BookAppointmentResult`'s success
   branch inherits that `any` — **the discriminated union added in §1 looks type-safe
   but isn't on the payload.** Root cause is `transformAppointment(appointment: any)`
   in `appointments.ts`.

## 10. Transferable lessons

1. **Client-side validation is not validation.** A disabled button guards nothing
   across two browsers.
2. **Only the database can settle a race.** App-level checks always have a window.
3. **A fallback must guard the condition that actually occurs.** `imageUrl ? … : …`
   tests for *missing*; the failure mode was *unreachable*. Test for load failure,
   not for a missing string.
4. **`tsc` passing ≠ it compiles.** RSC rules ("use server" exports) are enforced by
   the bundler, not the type checker.
5. **Dev and production diverge on error messages.** Next redacts thrown server-action
   errors in production. Return failures as data.
6. **Declared image dimensions define the aspect ratio,** not the file. Wrong numbers
   distort silently.
7. **Clear `.next` on every Next major upgrade.** A stale cache produces error
   messages that point at entirely the wrong thing.
8. **Verify the fix bites, don't just verify it exists.** Checking that the index
   existed would not have proven it rejects duplicates; attempting the duplicate did.
9. **Grep the compiled CSS** before trusting a new Tailwind utility — `@utility` failed
   silently.
10. **Responsive design has two axes.** A 1366×768 laptop is wide *and* short; width
    breakpoints alone gave it desktop spacing in a small window.
